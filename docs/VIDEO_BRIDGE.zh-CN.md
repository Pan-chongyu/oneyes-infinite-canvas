# 视频模型与冷启动恢复

## 请求与参数

OneYes 的已核验目录覆盖 23 款模型。模型名称展示分辨率、时长和人民币参考价；同渠道的 canonical ID 与精确可调用别名合并显示，保留已选中的完整值、渠道与 Key。售价已包含当前成本加价 10%，仅供参考，最终账单由站点结算。Token、参考视频、积分等动态费用不伪造固定总价；冲突倍率标为“不确定，按实际结算”。

- 88API：Wan 首尾帧与普通参考分开，同一素材去重、冲突 ID 明确报错；Seedance 使用布尔值；MiniMax、Google、Kling 分别构造已核验的媒体结构；Omni 1.1 为整数 3–10 秒，1.2 为整数 3–15 秒。Grok 桥使用比例和分辨率，不发送像素 size。
- 智赢：只使用支持的 `aspect_ratio`、`resolution`、`duration` 和素材字段，文件各传一次。实际序列化 multipart 后检查 **8 MiB**，包括 boundary、UTF-8 与文件字节；超出在付费提交前说明，不缩小原图或降低质量。
- 价格资料仅用于明确 OneYes 目录，不能限制第三方站点、请求脚本或未核验原生池。裸 `grok-imagine-video[-1.5]` 继续原生 Grok 通道；精确带价格的桥别名才使用 88API 请求。此处不会仅按名称前缀猜测提供方。
- 旧项目不支持的组合原样保留，要求主动选择。不会自动降低分辨率、裁切、缩短时长、更换模型、通道或生成方式。Veo 所需 PNG 使用原尺寸无损编码，不更改本地原件。

## 任务保存与恢复入口

桌面版在 `app.getPath('userData')` 持久目录保存 `video-tasks.enc`、`video-tasks.key` 和 `video-results/`。安装版通常位于：Windows `%APPDATA%/OneYes Canvas/`、macOS `~/Library/Application Support/OneYes Canvas/`、Linux `~/.config/OneYes Canvas/`；开发版名称可能不同，Electron 的实际 userData 路径为准。不会放在 temp 或每次启动清空的 media-work 中。

任务清单 AES-256-GCM 加密，使用当前本机文件加密方案，不调用钥匙串。同一系统用户也能读取本机密钥，不能宣称能抵御已控制该账号的进程。API Key 沿用既有加密配置，不写入任务清单；清单只存不可逆 Key 指纹、原站点、渠道、账号、模型、原始设置、实际发送的参数摘要／请求哈希、本机提交编号、回执 ID、项目／节点、时间和阶段。成片的过期签名 URL 不作为恢复凭据保存。

1. 付费创建前先持久化本机提交记录，关联画布节点；协议处理器在发送前保存提交阶段，在将回执返回页面前可靠写入 ID。同一本机编号的并行提交串行校验，只放行一次。采用临时文件、文件同步和原子替换；Unix 同步父目录，Windows 使用文件同步能力。
2. 每次冷启动由主进程加载记录，沿用原有 2.5 秒查询周期，只 GET 原回执，遵守服务端 Retry-After，等待时刻也随清单保存。不必打开对应画布。凭据与账号不符时暂停并显示原因，网络不可用保留任务，恢复后继续；不设整体等待期限或轮询次数上限，不按本机离线时间认定失败。
3. 每次下载前重新查询原任务获取有效入口。本站内容中继使用原 Key，外部媒体匿名获取，不带 Authorization 或 Cookie。原生 Gemini 使用 operation 查询及其受支持的媒体接口，密钥仅发送原 API 主机。
4. 下载写入 `video-results/<本机提交编号>.part`。有强 ETag 且服务器支持 Range 时校验续传；否则重新下载同一结果。完整写入后同步文件，检查响应长度、FFprobe 可读取的视频流／尺寸／时长、SHA-256，再原子改为 `.video` 并记录已保存。重启遇到已改名但清单尚未完成的文件会重新验证复用，避免重复素材。
5. 工具区的“视频任务与恢复”按钮打开列表：查看任务 ID、模型、参数与阶段，手动“重试查询／下载”或“保存视频”。原画布存在时回填原节点；项目或节点删除后保留任务，可从列表保存，不擅自重建节点。已保存的视频使用固定本机键，导出和 WebDAV 继续读取原件。
6. 创建无 ID 或响应不确定时显示“提交待核实”。本机编号与请求哈希只供核对，不冒充服务端幂等能力。没有原回执时不能自动恢复，也绝不自动重新 POST。审核失败、上游明确取消／过期、查询 404／410 显示真实原因并保留记录；认证失效等待恢复，磁盘失败保留成功未下载任务。

历史项目没有原账号身份信息，不能凭当前账号静默认领：保留原模型／节点／任务 ID，进入“待确认原账号”，用户确认当前渠道属于原账号后才查询。缺模型或已删除渠道保持可见错误，不能静默用新的收费模型替换。脚本模型仍由脚本负责创建与查询，未提供持久回执的脚本不能宣称支持冷启动恢复。

## 实际边界及服务端配合

- 客户端不删除未下载的可恢复结果，不设清理期限；**上游任务和成片的保留期限由站点／提供方决定**，目前交付资料没有可统一承诺的期限。若上游已删除，客户端不能凭空恢复；请及时保存或备份原视频。重装并删除 userData、磁盘损坏也可能丢失本机记录。
- 目前没有可供普通客户端调用的智赢公开文件上传接口。所需最小能力：经原用户 Key 鉴权的素材上传入口，返回文件 ID、真实 MIME／字节数／视频时长，创建接口接受这些 ID，并公布格式／大小、有效期与清理规则。不要暴露内部供应商密钥或 internal 上传地址。
- 88API 要求公开 HTTPS 的参考视频／部分图片，目前本地视频不可伪装为 Base64 直接提交。需站点提供受支持的上传／托管能力才能进一步简化操作。
- 希望 `/models` 或模型元数据明确返回路由提供方，区分同名裸 Grok 模型对应的原生池与桥池；提供鉴权的任务列表／本机幂等编号查询，可恢复“创建已受理但回执未达”的任务。目前只明确保留待核实状态。
- 客户端不处理生产账单、余额、供应商 Key 或历史重算。Redis 参数快照不当作实际请求证据；实际发送摘要与 UI 设置分别保留，不能据快照静默更改画质。

## 验证

`npm test` 包含视频队列子进程冷启动和真实 FFprobe 文件校验；`npm run test:videos` 使用 Electron 原生协议、Fetch、Worker 和 23 款模型请求；`npm run test:models` 覆盖准确模型 ID、下拉、复制 @ 引用和恢复列表。设置 `ONEYES_BRIDGE_TEST_DIRECTORY` 指向站点提供的本地桥目录，可额外用生产 normalizer 验证真实请求字节；该服务端源码不复制到公开仓库。

冷启动模拟强制结束测试进程并重新创建，覆盖生成中、完成未下载、半途下载、长期离线、凭据恢复、过期结果 URL、保存失败、原生 Gemini、审核／404、历史项目确认、不确定提交、Retry-After 冷启动与重复提交保护。恢复期间每个新任务的创建请求总数为 **1**；历史导入任务为 **0**。没有重启用户电脑，没有新建付费视频任务，模拟通过不代表所有上游实际成片质量已验收。
