# OneYes Canvas OTA 发布规则

从 v0.20.210 起，同一资源的所有 Range 请求复用已验证来源的 GitHub CDN 下载地址，不逐片调用资产 API。缓存地址明确返回 401／403／404／410 时移除并重新解析；每次检查更新清空下载地址及 Release 快照，避免旧 latest 被重复使用。API 限流、鉴权失败或临时网络／服务异常时使用原 GitHub 官方下载入口，已读取的 latest 快照固定到同一标签；未取得快照的 latest 仅允许同一仓库／文件到固定标签的官方跳转，之后验证 CDN 来源。明确缺失的版本／资产、取消和非法重定向不触发该回退。API 及入口请求避免重用旧重定向缓存，只向 GitHub API 发送构建令牌，存储与直链仅传 Range／If-Range 等必要头，不发送身份 Cookie。所有路径仍须通过原清单签名、目标身份、索引与完整包哈希验证，不接受镜像或修改现有公钥。没有增加网络重试次数、并发或时间上限。

新清单保留 schema 1、固定更新地址、公钥和完整安装包字段，将增量索引放在签名 rangeBlockmap 中，不再给旧更新器发布 blockmap。旧版忽略未知字段，使用已有的完整包下载、续传、哈希与原生安装；新版读取 rangeBlockmap，仍兼容历史 blockmap 基包与索引，后续增量不受影响。正式发布必须冻结 v0.20.207 原始解析器、下载器与更新器做回归，验证全部十种目标及真实原生中断／重启续传，不能只模拟新解析器忽略字段。若旧版的 GitHub API 配额已耗尽，仍需等服务恢复后重试；发布清单可避免再次耗尽，无法替已安装代码绕过服务端当前限流。v0.20.209 未发布，相关修复合并到 v0.20.210。

`test/build-download.test.mjs` 覆盖 100 次片段仅解析一次、缓存过期、416、取消、限流／临时故障官方回退、来源与凭据隔离，以及回退路径对篡改签名／包的拒绝。`test/blockmap-update.test.mjs` 在模拟匿名 API 配额下完整重建 macOS ARM64 的 100 个变化片段；六平台 `test:ota-ui` 使用真实 Electron 原生请求与 HTTP 服务，核验相同路径及 Range／If-Range、中断恢复和界面状态。

从 v0.20.207 起，十种 OTA 目标都发布 gzip／v2 `.blockmap`，并将索引文件名、固定版本 URL、大小与 SHA-256 绑定到原 Ed25519 签名清单。Windows 使用稳定版 electron-builder 的 `store-asar`，把业务 ASAR 独立于压缩运行时保存并采用官方细分块；FFmpeg、Codex 与其他未变化的二进制仍可按原字节复用。首次切换打包布局的下载可能较大，此后的实际变化量由分块计划决定，不承诺固定节省比例。

六种平台构建后生成并校验全部十份索引，保留 NSIS 已生成的细分块，不改写安装包。十个独立验证任务从同一份已签名旧版本清单下载对应基包和索引，沿用 electron-updater 的块匹配与生产重建器，只读取新版变化区间，最终核对完整目标 SHA-256，写出 `OTA-BLOCKS-*.json` 实测报告；无法复用的目标明确记录全量下载。最终签名任务必须核对全部报告的版本、目标、源／目标哈希、索引及字节计数，不再重复下载数 GB 的旧包，也不运行经常无法产出的全压缩安装包 BSDIFF。缺报告或身份不一致即停止发布，不以“跳过差分”伪装成功。

客户端保留当前基包与已验证索引，跨过中间版本也可直接比较当前与目标索引。Windows 首次安装或手动覆盖后，可接管 NSIS 已保存的 `installer.exe`；先从固定当前版本地址读取并验证签名、原生架构、格式、大小和完整哈希，再复制核验、原子提升为基包，最后删除仍匹配的重复缓存。缺失或损坏缓存继续使用签名完整包，不为启用增量去下载旧安装包。重启后的已就绪更新保持本次实际下载量和节省比例，历史包沿用原清理规则。macOS／Linux 旧版升级到首次支持签名索引的版本仍需全量，后续可复用。当前仍由原生安装器应用完整重建结果，不声称已经实现业务文件热替换。

`npm run test:ota-package` 在 Windows x64／ARM64 构建两个真实 NSIS 安装包，以微小业务变更验证静态资源没有整份重下；随机字节仅用于隔离测试，不是产品大小限制。`node --test test/blockmap-update.test.mjs` 覆盖全部目标、签名缓存接管、跨版本、断点、损坏、回退与重启，六平台 `test:ota-ui` 还通过真实 Electron HTTP 连接验证十种目标的中断续传。没有调整现有检查间隔、网络重试、下载并发或用户素材限制。

macOS 菜单栏图标使用独立的 `trayTemplate.png`／`trayTemplate@2x.png`，分别为 16×16／32×32 黑色＋透明通道，保留 Template 命名和显式模板标记，不再经 resize 丢失 2x 表示。两种 macOS 架构的安装包冒烟必须核验实际打包资源可读取、模板标记、16px 逻辑尺寸、1x／2x 像素与透明轮廓；系统负责深浅菜单栏和选中状态渲染，人工确认视觉效果。保留显示／退出菜单、关闭到托盘和原 OTA 流程。

Windows 安装器 `customInstall` 必须在替换程序后部署按 ICO 内容 SHA-256 命名的图标，更新当前用户／公共桌面、开始菜单和已有固定任务栏中目标经 Windows GetLongPathName 统一 8.3 短路径／长路径后精确匹配本次安装 EXE 的链接，并通过 SHChangeNotify 通知更新。使用原生 IShellLinkW／IPersistFile 读写，避免 WScript.Shell 在非中文系统中读取中文路径的目标为空。保留参数、工作目录、名称和 AppUserModelID，不重建删除入口、不操作其他安装、不重启 Explorer 或删除全局缓存；刷新失败不阻止新版打开，安装器详细日志保留结果。原生 PowerShell 明确使用系统模块，避免继承 PowerShell 7 环境导致命令不可用。Windows x64／ARM64 的 `test/windows-update.test.mjs` 通过实际配置的 NSIS hook、中文／空格目录、真实 Electron Shell 链接和任务栏应用标识核验，重复刷新不改链接；六平台签名、公钥及增量规则不变。手动工作流可启用 windows_icons_only，先在 Windows x64／ARM64 独立运行同一原生安装回归；正式标签仍执行全部六平台测试与签名发布，不以定向回归代替完整验收。

Windows 图标尺寸调整须核对 ICO 的全部 16–256 像素帧，圆角底板铺满边界且透明角保留，占比与 OneYes 主客户端一致；不能给已裁边图案再次添加透明外边。EXE、安装／卸载和窗口共用此资源，沿用 NSIS 的 Shell 图标刷新；macOS 的图标留白独立保留。

剪贴板改动必须覆盖当前 Electron 的真实异步 API：安装包冒烟通过系统剪贴板写入文字和 PNG／文字混合内容，再经生产受信主窗口 IPC 读取，在 renderer 中解码图片、核对尺寸与 MIME；测试结束恢复原剪贴板。只模拟旧 `readImage()` / 同步 `readText()` 的测试不能作为兼容性验收。浏览器权限不得代替桌面原生通道；失败诊断不含剪贴板内容。

OneYes Grok 本地图片发布须在桥已部署确认后启用。六平台 `test:videos` 回归精确裸名／价格别名、首帧／参考模式、Worker 原尺寸无损编码、公开 HTTPS 与本地图顺序、当前 Key 目录准入及第三方原生行为；本机可用 `ONEYES_BRIDGE_TEST_DIRECTORY` 指向已部署版本的本地适配器，验证真实 renderer builder→bridge normalizer→受信上传计划，不发起网络上传或收费创建。原任务、幂等和未知提交不得因能力开放而重放。

画布更新入口位于顶部工具栏，其他页面保留默认入口；六平台 `test:ota-ui` 必须验证只有一个入口、明暗主题与窄窗口下长标题不覆盖状态、弹层向下展开且不越界、外部点击和原生 Esc 关闭及焦点恢复。面板位置变化不得改变后台下载、更新前保存、忙碌保护、签名／哈希、增量、续传和安装重开。截图等待真实弹层动画完成，不以两帧截图替代最终布局检查。

大素材繁忙的幂等重试测试冻结 `Date`，明确验证 Retry-After 前一毫秒不能提交、到达时刻只允许原键／原正文／原地址／原 Content-Type；不以构建机真实时间或增加等待长度消除偶发失败，实际重试规则保持不变。

桥诊断使用服务端实际返回的 JSON 顶层 `bridge_request_id` 或 `X-Request-ID`，不依赖网关不会转发的自定义请求关联头，不为验证诊断创建收费任务。复制只使用客户端收到的公开任务回执与受控 brID，不读取或显示内部上游任务号；输出阶段、本地可读时间、时间戳与时区便于查询。缺失 brID 时保留原任务号和原时间，网关编号单列，不阻断取回。

视频诊断更新必须回归精确 `br_[a-f0-9]{32}` 的正文／响应头读取，创建、最新查询与二进制取回分阶段持久保存；不可用 brID 代替 taskId。复制诊断使用独立本机记录编号，排除完整幂等键、凭据、提示词、媒体地址、路径和原始响应。网关替换正文的 409 保留原未知提交与幂等记录，仅保留可核验网关编号，不重发 POST。重启恢复、网页记录和原生节点复制须离线验证；旧服务未返回诊断编号时留空。五款 Seedance 特价模型按精确能力走 `/videos` 二进制参考图，六平台原生回归覆盖原始价格别名、Worker 实际 MIME、字段和既有恢复逻辑。

视频桥错误更新须验证桌面和网页的固定公开 code：素材格式／尺寸／数量、时长／分辨率／比例、内容审核、提示词长度、暂不可用及任务终态。查询／下载 HTTP 422 中明确的五种临时代码沿用既有 GET 间隔及 Retry-After，无任务期限或次数上限，不新增 POST；持久化错误码与原回执，冷启动只恢复已保存临时代码且无服务端终态的记录。仅剩旧通用文字时不能猜测原始错误。HTTP 200 的 failed／error／expired／canceled／cancelled 读取本次 code，queued／processing／completed 忽略历史 error；终态保留回执但停止自动等待，未知提交只保留核实入口。回归覆盖进程终止、等待跨重启、原 scope／素材／参数、节点浅深主题和普通详情脱敏，签名及全部 OTA 目标不变。

安全素材错误发布回归覆盖明确的 `invalid_reference_format`、素材数量／大小、时长／分辨率与参数错误码，客户端只输出对应固定中文操作提示，不回显服务 JSON。同步提交失败、异步失败及原生 IPC／日志重启均保留具体原因、原参考素材／参数与已知任务 ID；未知提交仍优先保留原记录，禁止付费自动重发。`test:video-workflow` 核验节点正文可见、浅深主题与重开持久化。Retry-After 边界测试同时模拟 Date 和定时器，保留到期前一毫秒不重试的校验。

动态模型状态发布须在六平台执行 `test:models`：匿名固定本站 feed、真实脱敏 28 行样例、状态优先级、已下架／暂不可用／暂停新建、延迟／价格／参数待核实、失效 JSON 与 660 秒自然过期、60 秒时钟容差及缓存恢复。公开 feed 不能授权模型或修改原请求 ID；创建仍实时验证当前 Key，已有回执 GET／下载与重启恢复不受新建门禁影响。`npm test` 覆盖服务端有效新价优先、参数待核实不回退已核价、未知状态不推断下架和卡住的公开查询不阻塞允许的生成。签名和全部安装目标保持不变。

模型下拉框原生鼠标回归须等待真实滚轮的 `scrollend` 及键盘滚动定位后的布局完成，并确认鼠标实际命中对应可用行后再按下／释放；保留真实点击、关闭菜单、精确选择和画布无拖动断言，不以脚本直接选值代替。

视频模型展示发布沿用六平台 `test:models`：核验 26 款公开审核样例、完整尾部方括号、金额和计价单位、原名精确归并与当前返回 ID 优先级、旧请求 ID 持久化、中文与信息搜索、两行深浅主题及窄窗口；Video 分组的无价筛选不得影响文本／图片列表。样例不扩大当前 Key 权限，价格仅供展示，不构造付费参数。Veo Fast 能力变化须独立回归合法分辨率／时长、参考图固定 8 秒和完整 JSON／二进制请求 ID，不从价格后缀推断协议。签名公钥、下载续传、增量及全部 OTA 目标沿用。

统一视频桥接核对保留公共站点／用户 Key、原生 Grok 创建结构、精确模型权限、128 MiB 正文校验和固定错误白名单。六平台 `npm test` 覆盖成功排队／空 202 和下载失败的 Retry-After，独立进程重启保存等待时刻并只 GET 原回执，cancelled／canceled、failed、expired 分开持久化且终止自动查询。浏览器回归验证查询与外部下载退避、编码不透明任务 ID、不向外部媒体传站内凭据；`test:video-workflow` 保留节点原因和参数、浅深主题及重开，并覆盖服务端取消。所有新增验收均离线／mock，不调用付费视频；服务端依赖见 `docs/VIDEO_BRIDGE_AUDIT.zh-CN.md`。

六平台 `test:models` 验证浮动工具栏在复制节点、缩放、窗口四边、侧栏与真实 CSS 位移时按实际 DOM 锚定，自动翻转避开当前节点、标题及顶部栏；深浅主题、停止按钮颜色与原生鼠标点击均需通过，离屏节点不留下悬空工具栏。既有模型下拉菜单、偏好、批量引用和任务恢复回归保留。

视频审核提示回归只使用本次公开响应的明确拒绝语义或已核实分类；generic 500 不按内部日志猜测原因，不从 HTTP 状态／中文提示推定未提交或未扣费。六平台单元回归验证 type-only 未知提交与旧白名单文案的优先级，真实 `test:video-workflow` 验证具体原因在 IPC、恢复、节点本体和重开后保持一致，带本站请求编号并在浅深主题下可读；整个流程不触发真实付费请求。

视频目录退役回归由六平台 `npm test` 与 `test:models` 验证旧精确 ID 隐藏、原选择提示不可用、参数／偏好／未知任务不变，用户显式选择后才切换，不把按秒模型映射为 Token 计价模型。`test:video-workflow` 通过真实画布重开与取回按钮验证已退役模型仍可恢复原回执；API 回归核对原任务／content 路径只 GET、原凭据、无模型参数、零目录读取和零付费 POST。

无可靠回执的节点在真实画布中覆盖 unknown／submitting／prepared／not_submitted 四种记录，并分别通过错误覆盖层、工具栏和原节点参数面板进入原任务核对。原记录保留，目录读取、prepare、adopt 与生成 POST 均为零，不能借“重试”或原节点生成按钮覆盖未知收费结果；新配置节点仍可明确发起新任务。

逐模型视频偏好由六平台 `npm test` 校验 23 款最低配置有效性、别名共享与模型隔离、主动切换与重复选择和重开参数保留；`test:models` 用真实偏好输入验证自动保存、存储恢复、切换应用与一键重置，不提交付费任务。默认值只在主动切换事件应用，恢复和失败不得降级。

视频用户界面使用中性提示，六平台 `test:videos` 核对已知供应渠道名称及地址不出现在提示中，同时保留模型版本、生成参数、错误原因，不能通过修改实际请求配置隐藏渠道。内部诊断与原任务恢复身份继续保留。

创作工具的取消、切换画布和删除节点回归必须等待原任务 Promise（含清理）结束后再复用测试节点，不能用固定休眠推断清理已完成；中断恢复、原件保留和跨画布隔离断言继续执行。
