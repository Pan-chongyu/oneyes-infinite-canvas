# OneYes Canvas OTA 发布规则

视频 AI 超采样须用内置 ESPCN 实际增强每一原始帧，同一视频复用模型 Worker；2× 输出由用户明确选择，不能按模型参数伪造倍率。`test/video-upscale.test.mjs` 校验变帧率及末帧时长、旋转、精确输出尺寸、全部音轨与片尾时长、损坏帧拒绝、取消和临时文件清理；`test:creator-codec` 离线执行真实模型并验证不同帧顺序复用同一 Worker。图片及视频共用的 ESPCN 5/3/3/3 卷积分块必须保留五源像素上下文并裁去边缘；真实模型回归须对比跨块大图与移动位置后的单块参考，覆盖横纵交叉及部分边缘块，不能用模糊接缝或普通插值代替模型正确输出。HDR 和透明视频须在增强前明确拒绝。全程不增加固定客户端时长上限，不自动降低源素材分辨率。

v0.20.95 媒体等待回归覆盖生图请求／SSE／素材下载无客户端截止时间、图片过期提示仍查询原任务、超过旧 120 轮的视频等待与媒体脚本默认及显式旧超时。原生协议以隔离任务验证临时 503 后继续 GET、130 轮后下载与主动取消；跨进程生图恢复使用已过期的回执提示并实际取回无 CORS 原图，断网恢复只查询原任务，不重发付费 POST。原有 2.5 秒间隔及服务端 Retry-After 保留，服务端明确失败／取消／过期、HTTP 404／410 与鉴权失败仍处理；不取消上游服务的真实生命周期或承诺永久取回。六种平台／芯片运行对应测试及打包冒烟。

Seedance 视频回归按 OneYes Grok 分组识别标准 JSON 协议，验证水印／配音的布尔类型、登录和手动 Key 的准确渠道、单图／首尾帧／多参考／音频与原始像素。不得把 xAI 模型专属的分辨率限制套给 Seedance；上游 `task not found` 必须停止等待并显示核对官网记录／用量的中文提示，不切换协议重发。CI 使用隔离模型，不把 HTTP 200 任务回执描述为已生成成片。

Canvas 是独立 Electron 应用；本通道不修改 OneYes Desktop 的 Tauri/Sparkle 更新器和签名身份。

Windows 从 v0.20.93 发布两份 electron-builder 原生 `.exe.blockmap`，各自的文件名、固定 Release 地址、大小与 SHA-256 写入同一 Ed25519 签名清单；汇总缺失或损坏索引时禁止发布。`SHA256SUMS-blockmaps.txt` 单独保存索引校验值，`SHA256SUMS.txt` 仍仅含 12 个完整安装包。缓存保留当前版本签名清单与经 SHA-256 核验的完整 EXE，使用固定版本 electron-updater 的块匹配逻辑复用相同数据，只对变化区间请求 Range；不需要生成耗时的全安装包 BSDIFF。旧 BSDIFF 通道保留供已有版本和其他平台使用。

Windows 分块下载将签名源／目标安装包及两份索引哈希绑定到临时收据；跨进程重试从实际已写入位置继续，强 ETag 使用 If-Range。完整重建后及安装前均核对签名目标 EXE 的大小与 SHA-256。网络中断保留进度；索引／源包无效、Range 不受支持、字节范围错误或重建哈希不符时清理分块临时文件并使用签名完整包；本地磁盘／权限错误直接显示可重试错误。沿用原检查周期及重试规则，不新增限额或并发。进度只统计本次变化数据，显示节省比例，索引准备及最终校验独立显示。

已有 v0.20.92 及更早版本没有签名块索引，升级 v0.20.93 使用完整安装包；成功启动时保留该签名完整包，下一次同原生芯片升级可进行分块增量。Windows x64／ARM64 回归覆盖重新排序的块复用、断点与损坏前缀、索引和源包校验、服务忽略 Range／错误范围、原生 Electron HTTP 断开续传、离线已就绪恢复；真实 electron-builder 索引和 NSIS 安装验证中文／空格目录、父进程退出、目标版本、安装失败和自动重开。六平台打包冒烟离线加载实际块匹配依赖并重建参考文件，不能只在开发目录验证。

智能剪辑使用随包迁移的 Velocut 完整编辑器。六种平台／芯片运行 test:editor 和 test:smart-edit，覆盖独立受限窗口、真实多轨命令、素材原件／同名不覆盖、模型准确渠道及先审阅后应用、撤销重做、原尺寸与音频导出、回填幂等和跨进程恢复。不调用付费模型。Linux 无显卡 CI 沿用上游 browser-options 的 SwiftShader Vulkan 配置，并实际清屏／提交／读取原测试尺寸的 VideoFrame，不因 adapter 存在就认定渲染可用；该完整探测失败只允许 CI 记录 GPU 特性与失败原因并明确标注渲染未验证，编辑／AI／保存／重启测试仍执行，普通环境不得跳过，仍须验证保存和 AI 交互；可用设备必须真实导出，不通过降低分辨率通过测试。旧的 FFmpeg editAnalyze／editRender 仍作为媒体底层回归，但不再描述为当前剪辑界面。

底层 FFmpeg 的 editAnalyze／editRender 继续覆盖多音轨、镜头时间、图片混排、顺序、叠化、配乐、中文标题／字幕、原始尺寸、非法时间／播放列表拒绝和取消清理；这些属于媒体工具回归，不代表新剪辑界面支持字幕批量精剪。独立编辑器使用上游 WebGPU／WebCodecs 渲染，另验证关闭原画布或切换项目后 AI 请求立即结束，后续请求明确提示重新打开节点，重连不重发已完成模型请求。

macOS 权限回归必须验证隐藏 Agent 面板时不请求模型、Skill、线程或对话预热；后台桥接仍能提供经 token 鉴权的 Canvas MCP。隔离服务使用模拟受保护工作区与会写启动标记的外部 MCP，覆盖首次启动、保存活跃线程后重启、显式初始化与权限拒绝；普通启动不能访问工作区或启动外部 MCP，拒绝授权保留会话与用户配置。内置 Agent 及 Codex app-server 使用固定配置目录作为进程工作目录，不继承 Finder／终端目录。六种平台／芯片执行原生界面与服务回归，macOS 打包启动还需核对桥接启动后工作区未创建；不重置 TCC、不禁用系统保护、不发送付费模型请求。自选受保护工作区或主动使用电脑控制工具时，macOS 仍可请求授权。

导演台关闭回归必须挂载真实 `InfiniteCanvas` 与 `CanvasNode`，以原生鼠标按下／松开验证关闭按钮和遮罩，并以原生键盘验证 Esc 与聚焦关闭按钮后的空格操作；不能只用 DOM `.click()` 代替。弹窗内操作不得触发底层指针捕获、选择、拖动、缩放或右键菜单；关闭后画布正常可用，重开与进程重启仍保留镜头和场景。无 GPU 的 Intel CI 分支同样验证关闭交互。

导演台编辑回归还须覆盖连续字段撤销合并、原生撤销／重做与删除快捷键、锁定保护、隐藏／恢复、实际几何贴地和聚焦；输入控件与修饰键不能误删物体。原生键盘事件发送后，必须等待 renderer 实际收到 keyup 且完成下一帧，再断言未变化或执行解锁，避免尚未处理的删除事件跨过测试步骤。保存机位包含相机及原始输出尺寸，恢复与跨进程读取保持一致；构图线与选中框不得进入 PNG，重复输出不能重叠。浅深主题验收须同步真实主题 store 与组件主题，不能只切换页面 class。机位与场景持久化，撤销栈只在当前编辑期间保留。

3D 导演台必须在六种平台／芯片执行 `npm run test:director`：使用生产打包的懒加载模块，经真实 `oneyes-canvas:` 协议离线启动 WebGL，验证场景校验、人物姿态／焦距变化、精确 PNG 像素尺寸、显卡超限拒绝与资源释放，检查浅深主题、结果连线、原图本地存储和跨进程场景恢复；切换项目时关闭旧编辑器，防止结果保存到错误画布。GitHub macOS Intel 虚机没有 Metal GPU，Electron 44 的 SwiftShader 也无法初始化（electron/electron#53994）：仅当该 CI 平台真实 WebGL2 探测失败且原生 GPU 状态明确禁用时，改为验证离线模块、硬件加速操作提示、禁止导出、参数保存／重启与项目隔离，并在日志明确标注未验证实际渲染；其他五种构建仍必须真实渲染，Intel 实机效果待有显卡设备确认。不依赖 CDN，不发付费生成请求，不通过降低分辨率使测试通过。

本地创作节点的发布构建必须先执行 `npm run media:prepare`，按固定 SHA-256 下载各系统／原生芯片的 FFmpeg/FFprobe，并保留许可证与构建来源；不得误装模拟架构的媒体工具。`npm test` 的真实视频回归验证顺序、原尺寸、全部音轨、镜头表、禁止外部播放列表和取消清理。`npm run test:creators` 验证五类节点、重复点击、取消、删除／切换画布隔离和中断恢复；构建后 `npm run test:creator-codec` 通过原生协议离线加载实际 U²-Netp、ESPCN 模型及打包 WASM，核对 PNG 透明度、图层合成和精确三倍输出。关键帧提取使用新旧内置 FFmpeg 均支持的 `-fps_mode:v vfr`，不得依赖新版已移除的 `-vsync`；离线图层混合回归仅允许原生渲染的一个颜色值舍入差异，输出尺寸与透明度仍精确核对。六平台打包冒烟还必须检查媒体二进制原生架构、实际启动、真实主窗口 IPC／协议上传及原尺寸取回，macOS 保留深层 codesign 校验。禁止通过缩小素材或普通插值冒充 AI 超分来使测试通过；不发付费模型请求。

`test:creators` 使用生产编译的页面和 Worker，经真实原生协议读取不含 CORS 响应头的对象存储原图，验证签名查询参数完整、匿名请求、原尺寸及逐像素一致。必须覆盖批量图片主图选择、本地索引缺失但原始 Blob 存在、HTTP 403 与真正缺失原图的终态和诊断阶段；不得回退缩略图或重提交生成。

增量 OTA 使用随应用打包的 `bsdiff-wasm`，无需用户安装依赖；重建在可取消的桌面 Worker 中执行。六种平台／芯片的打包启动检查都必须离线应用参考 BSDIFF40 包，验证 ASAR 内 Worker 与 WASM 可用。发布端固定同一份上一版签名清单，十种目标在独立 GitHub Actions 任务中用系统 BSDIFF 并行生成补丁并重建目标；最终汇总再次重建校验，再由一个任务统一签名发布。单个大包差分生成超过两分钟或补丁不小于完整包时跳过该目标，保留签名完整包继续发布；已生成的补丁逐项核对目标大小和 SHA-256 后签名发布。`SHA256SUMS.txt` 保持只含 12 个完整安装包，兼容应用中心既有同步器；增量校验值另放 `SHA256SUMS-deltas.txt`，并由签名 OTA 清单绑定。

- 每个正式 Canvas 版本递增 `package.json`、`package-lock.json`、`VERSION`，提交并推送源码和同版本标签。公开仓库的 `desktop-release.yml` 必须完成六种平台／芯片构建、测试与打包后才发布。
- Release 必须包含 Windows x64/ARM64 EXE、macOS Intel/Apple Silicon DMG/ZIP、Linux x64/ARM64 AppImage/DEB/RPM 共 12 个完整安装包，另有 `SHA256SUMS.txt`、`canvas-latest.json` 和 `canvas-latest.json.sig`；有上一版完整包时还会发布按平台、芯片和安装格式绑定的 BSDIFF 增量包。缺失任一平台或签名身份不匹配时发布失败。
- `canvas-latest.json` 的原始 UTF-8 字节使用 Ed25519 签名；公钥固定在 `desktop/update-key.cjs`，私钥只放 GitHub Actions 的 `CANVAS_OTA_PRIVATE_KEY` 和本机忽略目录中的备份。不能随意换公钥，否则已安装客户端将拒绝后续更新；严禁把私钥提交到仓库或写进日志。
- 客户端固定读取 `https://github.com/Pan-chongyu/oneyes-infinite-canvas/releases/latest/download/canvas-latest.json` 及同地址 `.sig`。签名校验后，严格检查版本、仓库、标签、文件名、大小和 SHA-256。下载完成后及安装前均验证文件，损坏或不可信的包不得执行。增量清单同时绑定源包和目标完整包哈希；源包缺失、增量损坏或重建结果不一致时自动回退同一签名清单中的完整包。
- 启动时和每 6 小时检查，自动后台下载新版本；不开启退出时自动安装。完成后显示新版版本号，由用户点击“更新并重启”。失败保留当前版本并支持手动重试，已有完整且有效的新包在离线重启后可恢复。
- Windows 通过原生 `os.machine()`（GetNativeSystemInfo）识别芯片；macOS 检查 `hw.optional.arm64`，避免 Rosetta 错配；Linux 使用原生 machine。GitHub Actions 使用 `macos-15` 构建 Apple Silicon、`macos-15-intel` 构建 Intel。DEB/RPM/AppImage 使用独立平台键，包管理器仅识别安装格式，不用于推断架构。
- Windows 使用 NSIS 静默覆盖原目录，安装后重新打开；macOS 使用已签名清单中的 ZIP，校验 Bundle ID、版本、可执行文件与 ad-hoc codesign，等待新应用完成界面启动后才删除旧应用；AppImage 同样等待启动确认，失败回滚。DEB/RPM 调用系统 `pkexec` 获取正常安装授权，取消后保留原应用并允许重试。
- Windows 安装使用系统 PowerShell 引导独立隐藏助手：助手读取 UTF-8 计划并确认准备成功后，主程序才能退出；不得直接用 Node `detached: true` 启动 PowerShell，也不能让实际安装进程依赖主程序生命周期。助手等待主程序退出，再通过 .NET SHA-256 核对签名清单绑定的完整安装包；NSIS 的 `/D` 参数保持最后，支持中文与空格目录。成功退出且安装后的 EXE ProductVersion 等于目标版本才启动新版；失败记录准备、完整性、安装、版本或重开阶段，并在可运行时重开应用，界面给出对应处理方法。`test/windows-update.test.mjs` 使用独立临时目录、合成版本 EXE 和真实 NSIS，验证父进程退出后的安装、自动重开、安装失败／版本未替换／包被篡改和助手启动失败；不操作用户安装或注册表。旧版安装助手本身无法启动时，需要一次覆盖安装新版，保留本地数据后继续使用内置 OTA。
- macOS 当前保留 ad-hoc 自签名，不声称 Apple 公证；应用必须放在可写目录，推荐“应用程序”。不调用系统钥匙串，不更换用户的 API Key、Codex 或 MCP 配置。
- 更新缓存仅保留当前新版本的完整包或可续传进度，以及一份经过验证的当前版本基包。下载前持久化签名清单，`.part` 与其 URL／大小／SHA-256／强 ETag 关联；中断或退出保留进度，重试及重启按 Range／If-Range 续传。服务器返回完整 200 时重新写入；范围错误或 416 清除旧片段并取完整包。拼接后必须校验全文件 SHA-256，损坏前缀不得安装；增量下载中断继续同一补丁，补丁完整但校验／重建失败才回退完整包。安装完成、发现其他新版或格式变化后清理历史进度和增量临时文件。首次升级到支持增量的版本仍需完整包，后续同平台同格式升级才使用增量包。升级后首次成功加载界面即清理已安装及历史更新包。新版本准备失败时保留可继续运行的旧应用，不删除本地画布、账户或配置。
- UI 安装前检查活动对话并刷新画布本地持久化；用户需先结束其他媒体生成任务。应用中心仍保留首次安装／手动恢复入口。v0.20.20 及更早版本需从应用中心先安装支持 OTA 的版本，此后可使用内置 OTA。
