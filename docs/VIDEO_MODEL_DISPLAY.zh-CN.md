# 视频模型两行展示契约 · 2026-11-18

## 动态目录与状态

客户端固定匿名读取 `https://oneyes.ai/video-models/catalog.json`，不带 Cookie、API Key 或管理员身份；每五分钟、回到前台及模型菜单打开时复用缓存。`request_ids` 只按精确值匹配本 Key 已返回的 ID，`recommended_request_id` 只有实际获授权才可成为新选择。历史节点与任务保持原 ID，不由显示信息拼接请求值。

第一行显示模型原名和固定状态标签，第二行显示服务端 `model_info`。`retired` 显示“已下架”、`unavailable` 显示“暂不可用”，管理关闭新建显示“暂停新建”；以上阻止新的生成及重新生成，已提交任务的查询、下载、重启恢复不受影响。未知状态或一次鉴权／网络失败不推断下架，保留最近确认状态；旧模型条目保留可见，Key 权限缺失单独禁用，不冒充服务端下架。

JSON 生成时间超过 `refresh_after_seconds * 2 + 60` 秒（当前 660 秒）或明显在未来时保留最后有效缓存并显示“信息更新延迟”，未来允许 60 秒设备时钟偏差。缓存加载、断网、坏 JSON、空目录及目录请求失败也显示延迟，不整体停用正常模型；匿名元数据刷新不会阻塞用户生成，创建仍实时核验本 Key 模型权限。浏览器定时标记自然过期，前台事件按缓存刷新。

`price_stale` 显示“价格待核实”，`parameters_stale` 显示“参数待更新”。有效 feed 信息优先于较旧本机缓存，因为服务端已保留最后核价结果；只有显示字段缺失或无效时回退缓存。参数待更新不能遮住已经核实的新价格，也不改本地验证规则或已有配置。`has_price=false` 不进入新的有价 Video 选择列表；历史及退役显示保留。附带的结构化价格／能力不直接改变请求参数或当作计费证据。

回归使用脱敏公开样本 `test/fixtures/video-catalog-public.json`（26 可用、2 历史下架）；数量仅作该样本断言，不是运行时白名单。覆盖精确权限交集、状态优先级、暂停、失败缓存、自然过期、价格变动、原回执取回及浅深主题。服务端连续缺失判定由服务端负责，客户端不自行累加下架证据。

仅作用于 OneYes Canvas 无限画布的 **视频模型选择器**、其搜索结果及选中模型展示；不改变图片、聊天等模型列表。模型原名一行，价格和参数信息另一行。公开样例见同目录 `视频模型两行展示公开样例-20261118.json`，共有 26 个当前可用模型。

## 展示和请求值

```text
第一行：veo-3.1-fast
第二行：720p-4k 4/6/8s ¥0.165/秒起

实际请求 model：veo-3.1-fast [720p-4k 4/6/8s ¥0.165/秒起]
```

样例字段定义：

| 字段 | 含义 |
|---|---|
| `id`、`model_name` | 模型原名，用于第一行及同模型去重；不擅自替换实际请求值 |
| `request_id` | 服务实际接受的完整模型 ID，包含价格信息后缀；选择新模型时使用该值 |
| `model_info` | 第二行展示信息，不用于构造请求 ID |
| `display_name` | 原名与完整后缀的组合，保留供兼容解析 |
| `prices` | 已核实的人民币参考价分档，`amount_cny` 为十进制字符串，单位为 `per_second`、`per_generation` 或 `per_million_tokens` |
| `price_description`、`capabilities` | 面板补充信息，按需展开，不挤入第一行 |
| `reference_video_multiplier` | 若存在，则参考视频会影响适用价格；缺失时不自行推断倍率 |

展示字段永远不作为计费证据。实际账单仍随请求参数、实际消耗和任务成功结果动态结算；“起”表示最低适用档位，不代表所有参数同价。

## 解析和筛选

1. 优先采用服务明确提供的结构化模型原名、信息和请求 ID。现有 `/v1/models` 若仅有 `id`，解析 **完整末尾** `[信息]` 或 `【信息】`。保留原始 ID 的每一个字符用于请求，不 trim/re-encode/改写真实 ID。
2. 仅把尾部成对方括号中的价格/参数当作信息；中文模型名正常支持，名字中间的括号不能被误截断。信息必须含明确人民币数值和计价单位，例如 `¥0.165/秒`、`￥2.178/条` 或 `2.178元/条`，可包含“起”。不要把 `价格待定`、只有分辨率/时长、空信息或不成对括号当作有价信息。
3. 按模型原名精确分组，仅显示有价格信息的条目。若原名裸条目与带价别名同时返回，只显示一个带价项；裸条目保持服务端调用兼容。不要将 `wan3.0` 与 `wan3.0-video`、`grok-imagine-video` 与 `grok-imagine-video-1.5` 进行前缀合并。
4. 同模型的多个带价别名优先按结构化首选 ID 或本公开样例中的 `request_id` 选择，不靠字典序、字符串长度或“最后一项”猜新旧。当前 `veo-3.1-fast` 首选本文件的新 ID；旧 `veo-3.1-fast [720p 8s ¥0.165/秒]` 仍可调用，但不作为新建选择项展示。
5. 搜索应同时匹配模型原名和第二行信息，支持中文、分辨率、秒数和价格。用文本节点渲染服务文本，不把模型名或信息注入 HTML。
6. 若某个未来模型没有可核实价格，视频选择器暂不显示；不使用默认零价或其他模型价格填充。后续服务提供完整价格信息后自然出现，不能将本样例的 26 个 ID 作为永久白名单。

可以参考以下尾部提取表达式，再对提取到的信息执行金额与单位校验；不要仅凭正则匹配成功就认定有价：

```js
/^(.+?)\s*(?:\[([^\[\]]+)\]|【([^【】]+)】)$/u
```

## 兼容和验收

- 历史节点、正在生成的任务、重启恢复、幂等记录和模型权限继续使用原先保存的完整请求 ID；展示变化不能触发自动重建任务或重写历史 ID。
- 已选中的旧 ID 即使不在新建列表，也应保留该节点的原模型与任务记录；不要静默切到其他模型。需要新建选择时再使用当前首选 ID。
- 第二行可自动换行，第一行明确展示原名。选中状态、键盘导航、搜索和无障碍标签要保持可用。
- 测试至少覆盖：裸名+带价项去重、26 模型均有价、旧新 Veo 别名优先级、中文 `SD-特价`、中英文方括号、格式错误、缺价格/单位、价格为零的明确值、近似名字不误并、完整请求 ID 原样传递、历史恢复不变及窄屏显示。
- 用户界面只展示模型、参数和用户价格。不要加入渠道名称、地址、提供方成本、积分成本或渠道余额；本公开样例不含这些信息。
