# 统一视频桥接核对

客户端继续使用用户选择的 OneYes 公共站点与用户 API Key。Video 分组后的独立协议桥部署、通道调度和提供方协议转换由服务器负责，客户端不包含内部桥地址或提供方密钥。本次没有修改 Sub2API、图片生成或原生 Grok 创建协议。

## 已部署本地图片上传

OneYes 统一 Video 桥已确认开放两款 Grok 本地参考图，本版启用既有候选适配。仅当前 Key 授权的精确 ID 走此桥；本地图片经原尺寸无损 Worker 编码为 WebP／PNG，公开 HTTPS 原样保留，混合顺序不变。桥负责受信存储上传后创建，客户端不持有提供方凭据，不将原图降低分辨率；第三方原生行为、已知回执和未知提交保护不变。Grok 参考视频、编辑及上传音频仍不支持。客户端真实 renderer builder 与上线源码的本地 normalizer／上传计划契约验证不创建收费任务，也不等于新增真实成片验收。

## 核对结果

| 契约 | 当前实现与离线证据 |
| --- | --- |
| 当前 Key 的模型权限 | `video.ts` 每次新建核对该 Key `/v1/models` 的精确 ID；参数与价格来自已核验客户端目录，不要求模型接口返回 capabilities 或价格。API 回归拒绝旧缓存、另一 Key 和价格别名越权。 |
| 创建与素材语义 | 保留 `/videos` 和原生 Grok `/videos/generations`、各模型 JSON/multipart 与素材角色；二进制、布尔值、参考顺序及原分辨率回归保留。 |
| 不透明回执 | 兼容 `id` / `request_id`，原 ID 持久化，查询与 content 使用 URL 编码，不从前缀猜通道。 |
| 持久化和取回 | 原生协议交付响应前写入加密清单；保留原站点、渠道、账号、Key 指纹、模型与幂等键。独立进程强制退出后只 GET 原任务；原件落盘、长度、FFprobe 与哈希验证后才显示已保存。 |
| 未知提交 | 保留记录与原参数，显示待核实；原节点只查看原任务，不重新收费生成。429 只有明确 `large_material_busy` 可按原键、原正文重试，其他 429、网络和 5xx 不重发 POST。 |
| 退避和终态 | 本次补齐成功排队响应、空 202 及下载失败的 Retry-After，等待时刻随原生清单保存；浏览器也遵守查询／下载的 Retry-After。服务端 cancelled/canceled 单独显示“任务已取消”，终止自动查询；失败和过期继续分别保留。 |
| 安全错误 | 413、422、审核、未知提交等使用固定中文白名单进入节点并保存；不回显供应方、地址、密钥、资金信息或签名下载地址。通用 500 不猜审核原因，普通日志仅保留脱敏技术字段。 |
| 素材边界 | 序列化后校验完整 128 MiB（含封装），文本、内联和单模型额度分别校验；不静默降分辨率、压缩或丢弃素材。 |
| 价格 | 继续使用已核验的售价与成本加 10% 规则、原单位与条件档位，最终以本站结算为准；不读取内部 bridge_billing。 |
| 下载凭据 | 本站 content 用原用户 Key，外部成片匿名下载；原生回归确认外部地址没有 Authorization 或 Cookie，断链后重新 GET 原任务获取入口。 |

## 本次验证

- `test/video-recovery.test.mjs`：独立进程冷启动、原件校验、下载失败及服务端等待跨重启保存，取消／失败／过期不自动重新查询，未知提交不重建。
- Web 视频、桥正文、繁忙重试与模型目录测试：原生请求结构、长任务、GET 退避、精确权限、128 MiB、413/429、错误白名单与凭据隔离。
- `test:video-workflow`：真实桌面 IPC 与画布节点回填、持久化重开、浅深主题，包含已取消任务的安全文案；无付费生成。

上述是客户端模拟与离线验收，不是生产收费成片验收。各平台发布验证以正式 Actions 结果为准。

## 仍依赖服务器

原生 Grok 透明中继的上线和各通道真实可调度状态由服务器维护，客户端看到模型元数据不表示停用账号已恢复。生产 CDN 上传额度、模型素材限制、任务／成片保留期、用户 Key 的预上传入口和未知提交的鉴权任务列表／幂等查询仍需服务端提供或实测。现有服务曾包含视频计费、恢复与错误清洗补丁，不能称为未经修改的官方程序。本轮不新增服务端补丁，也不为验收创建付费视频。
