# OneYes Canvas 异步生图与恢复

参考图提交前按原始 Blob 的文件内容识别格式并实际解码，不能信任对象存储的 `application/octet-stream` 或节点标题的 `.png`。从 v0.20.30 起，所有参考图在可取消的 Worker 中按实际显示方向和原尺寸无损重编码为 WebP，去掉 EXIF/MPF/ICC 等容器扩展数据并压缩低效率的大 PNG；保留解码后的像素、透明度、顺序及本机原图，不缩放、不采用有损质量参数。WebP 编码不可用或尺寸超出编码格式能力时，按原尺寸使用无损 PNG，不额外引入大小阈值。编码器和 WASM 随安装包提供，无需用户安装依赖或访问 CDN。每张使用独立文件名和正确 MIME／扩展名，多图以 `image[]` 逐文件提交。损坏图片或 Blob 丢失时指出序号与名称，并在付费 POST 前停止；不丢弃失败参考图，也不重发任务。

OneYes 的 OpenAI 兼容模型默认使用 `POST /v1/images/generations/async`，参考图编辑使用 `POST /v1/images/edits/async`，提交参数沿用原生生图 JSON / multipart，且不发送 `stream` 或 `partial_images`。服务端返回 `202`、`task_id`、`expires_at`，客户端通过 `GET /v1/images/tasks/{task_id}` 查询。真实协议对应 Sub2API 的 `image_task_handler.go`，与 Gemini 的 `/images/batches` 接口不同；保留原有自定义脚本和 Gemini 调用方式。

发送前将本地任务及画布节点／多图槽对应关系写入 IndexedDB（localforage）；收到任务编号后立即持久化。断网保留任务，联网、重新打开应用或修复原 Key 后继续查询，遵从服务端 `Retry-After`，缺失时复用已有视频轮询间隔。每次请求沿用原有图片请求超时，没有新增总等待时长或尝试次数上限；到期时间以服务端 `expires_at` 为准，当前官网返回约 24 小时。

完成响应读取 `result.data[].url` / `b64_json`（或单图 `image_url`），逐张下载为本地 Blob，写入生成记录后才标记完成。下载／本地历史写入中断均保留原任务，下次继续取图；已保存图片不会重复下载。画布只恢复同一个项目、节点和图槽，后续新任务优先，不覆盖已成功的其他图。未打开的画布可在下次打开时恢复，生成记录仍会先保存取回图片。跨页面任务面板放在生图工作台，可继续取图或移除失败记录。

桌面端 HTTPS 结果图片通过同源原生下载通道获取，不要求对象存储开放浏览器 CORS；沿用已保存的代理设置及图片下载超时。仅允许 GET 图片／二进制内容，不向图片地址发送 API Key、Cookie 或代理认证请求头，保留签名 URL 的查询字节；拒绝图片源重定向和非图片页面。已生成但尚未存入本机时，原图槽显示“图片已生成，正在取回”，连接中断时显示重连状态。

任务记录只保存原 Key 的 SHA-256 指纹和业务元数据，不复制 API Key 或账户 Token；恢复必须在当前加密配置中找到原 Key，不使用后来切换的 Key。提示词、参考图及图片仍属于本机 IndexedDB 数据；不是云端画布同步。参考图持久化为图片 Blob，任务仅引用 storageKey。保留固定 OneYes 双域直连优先与只读回退，查询不采用远端提供的任意 poll_url，也不向图片 URL 附带 API Key。

当前服务端异步提交**没有幂等机制**，不支持按客户端请求编号找回未确认提交。因此任何提交超时、5xx、断线或无效任务编号都不会自动重发，也不会自动切回同步生图；显示“先检查官网用量，避免重复扣费”。只有已保存任务编号的查询和取图可自动恢复。明确的服务端失败、Key 无效／删除和任务过期分别显示处理提示。暂停本地等待不代表取消服务端已受理的任务，可从工作台继续取图。

验证：`npm test` 包含任务恢复、存储失败、多图、账号变更、过期与无重复 POST 测试；`npm run test:images` 使用隔离 Electron 和真实 IndexedDB，验证文生图／参考图编辑提交、断线后刷新页面、下载中断、历史与 Blob 落盘、原画布位置恢复。真实官网也验证了单次提交后结束进程，再以任务编号从新进程取回完整 PNG；不在日志或仓库保存 Key、账户 Token 或真实图片链接。

v0.20.27 的进程重启测试不再 mock renderer fetch：通过原生协议提交／查询任务，并下载无 CORS 许可的真实本地图片服务响应，先验证 renderer 直连确实被拦截，再验证原生取图、原图槽回填、二次重启缓存复用及没有重复 POST。六种发布平台／芯片构建都运行这项回归。
