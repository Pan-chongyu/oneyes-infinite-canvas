v0.20.26 修复 macOS 客户端重启后异步生图节点偶尔一直显示「生成中」的问题：启动恢复先等待本机任务库初始化，再按原任务编号、Key 和画布图槽恢复结果。任务记录缺失或槽位关联不完整时，显示可操作状态并提示检查官网用量，不会自动重复提交；有效的兄弟任务仍会继续取图。隔离 Electron 多进程测试验证重启、离线后恢复、本机图片 Blob 和原画布位置。

v0.20.23 延续客户端内置 OTA。启动与每 6 小时后台检查，发现新版本自动下载，签名和文件校验完成后在左下角显示版本号，点击“更新并重启”。支持 Windows、macOS、Linux x64/ARM64，依据原生芯片选择包，Linux 区分 AppImage、DEB、RPM；DEB/RPM 正常弹出系统安装授权。失败保留当前版本可重试，完整下载可离线恢复，更新成功清理旧包。macOS 保留自签名，验证应用身份后替换，等待新界面启动成功再清理旧应用；不调用钥匙串。安装前保存画布并检查活动对话，其他生成任务请先结束。旧版需从应用中心安装本版一次，此后可使用内置 OTA。发布包含 12 个安装包、SHA256SUMS.txt 和 Ed25519 签名 OTA 清单；不更改主客户端更新器。发布校验任务会安装清单生成所需依赖。

v0.20.20 修复回复后无法继续输入的问题。对话输入始终可编辑，回复过程中可以提前写下一条草稿；回复结束且会话就绪后，无需等待后台历史同步即可发送。发送仍检查连接、会话状态和正在执行的任务，切换会话时不能误发；过期历史结果不覆盖新任务，加载标记按请求归属释放。发送失败保留用户后来输入的新草稿。独立 Electron 回归测试覆盖连续发送、延迟历史、过期快照、回复中草稿、中文输入法和发送失败，不访问真实账户或模型。此 Canvas 版本通过应用中心发布六种平台／架构安装包。

v0.20.18 修复配置向导三个服务同时显示「请求失败」的问题：桌面模型读取改由主进程请求固定的 OneYes 模型接口，配置向导、连接诊断和手动刷新模型共用此通道，沿用已保存的 HTTP / SOCKS 代理，不依赖渲染进程 Axios 的自定义协议传输。网络不可达、代理认证、Key 无权限、服务异常与模型列表无效分别提供可操作提示；不展示服务返回的原始敏感内容，不重复创建已有 Key，失败保留原配置。更新后点击「重新检查并配置」即可复用已有 Key 重新读取模型，不发送付费生成请求。

v0.20.17 新增桌面内置 HTTP / HTTPS / SOCKS4、SOCKS4a、SOCKS5 和 SOCKS5h 上游代理。配置中选择「HTTP / SOCKS 代理」，填写地址及可选认证后保存即可使用；模型、媒体、WebDAV 和桌面账户请求统一通过代理，认证失败或代理不可达时不会改走直连。代理地址、账号和密码保存在桌面 AES 加密配置中，导出配置会清除凭据，日志和请求地址不会记录凭据。网页端继续使用本机转发服务模式；桌面版本不需要运行 Node.js。

v0.20.16 修复账户校验仍将视频分组限制为 MiniMax 的问题。独立登录和复用 OneYes Desktop 登录态现在都能按 Grok / Video 创建 Canvas_无限画布 Key；其他平台的同名 Video 分组仍会拒绝。

v0.20.15 将截图所列模型统一归类为视频模型，并把 OneYes 视频 Key 的自动创建、复用及手动配置目标切换为 Grok / Video 分组。旧 MiniMax 官方 Key 会在连接诊断中提示重新接入；保存的模型选择继续有效。此 Canvas 版本发布 Windows、macOS、Linux 六种平台／架构的安装包；不更改主客户端 OTA 更新器。

v0.20.14 新增首次配置向导：等待本机配置与账户恢复后，仅在未配置模型且未选择稍后时显示。已恢复 OneYes 登录态直接进入模型准备；否则可登录（支持双重验证）、复用主客户端登录态或手动填写 Key。一键配置沿用既有平台／分组规则，复用或创建 Canvas_无限画布，逐项检查生图、文本、视频连接；部分失败如实显示原因，可重试或先使用已接通的功能。失败不会标记成功，不发送付费生成请求。完成／稍后状态保存在现有桌面加密配置中，保留已有 Key 与默认模型，设置中的「更多」可重新打开向导。导入导出与手动 Key 收进次要入口，连接诊断与模型管理继续保留。此 Canvas 版本通过应用中心发布 Windows、macOS、Linux 六种平台／架构的安装包；不更改主客户端 OTA 更新器。

v0.20.13 在 Windows 桌面版自动补齐已配置 Windows-MCP 的运行依赖：先检查专用缓存和现有程序，缺失或损坏时从官方来源准备 uv 0.13.4、Python 3.14 与 windows-mcp 0.8.8，完成 MCP 握手和工具清单验证后接入当前对话。首次准备需要联网，下载 uv 校验固定 SHA-256；已准备的环境重复使用，无需管理员权限，不修改系统 PATH、全局 Python、原 Codex MCP 或模型配置。界面显示自动准备状态，失败保留具体错误，重新连接可重试。仅处理已启用的官方 uvx/windows-mcp stdio 命令，不替换自定义或远程服务；安装期间的配置变更优先。ARM64 Windows 使用原生 uv 和隔离的 x64 Python 兼容环境，因为官方 dxcam 尚无 ARM64 wheel；macOS/Linux 不安装 Windows 工具。发布工作流在两种 Windows 架构实测从零补齐、缓存复用及原生 Codex 接入，不发送模型任务或执行桌面操作。

v0.20.12 自动处理 Windows-MCP 初始化期间的暂时性握手断开：通过 Codex 原生 MCP 刷新重连一次，沿用原配置与启动超时，重新读取工具清单并显示重连结果。后续服务恢复也会同步清除过期红色提示；保留当前对话、模型、权限和其他 MCP，不重发模型任务。缺少依赖、登录授权和用户取消不盲目重试，重连失败仍提供解决步骤。

v0.20.11 将 MCP 启动失败提示改为可操作的中文说明，区分握手断开、缺少依赖、超时、登录权限、连接失败和取消，明确哪些工具仍可使用。失败项可展开解决方法、复制处理步骤，Windows-MCP 提供官方安装文档入口；原始错误默认收起。仅提供处理指导，不自动修改其他 MCP 配置或安装依赖。

v0.20.10 新增「一键永久接入 Codex」：桌面版内置本地 Agent、运行依赖和对应芯片的 Codex CLI，点击后自动启动仅监听本机的服务并写入用户级 MCP 配置；重启画布后自动恢复，无需安装 Node.js 或复制令牌。原配置先备份，保留现有模型、登录及其他 MCP；损坏配置不会被覆盖，失败可直接重试。外部 Codex 请新建对话加载画布工具，使用工具时需保持画布打开。接入画布工具不会代替 Codex 登录或配置模型 API。

v0.20.9 将 Markdown、SVG、HTML、3D 全景和便利贴五种节点直接集成到客户端。无需逐个安装，可从画布添加节点菜单和底部扩展节点菜单使用；Markdown 与全景渲染依赖也随包提供，不再运行时访问插件仓库或依赖 CDN。已有同类型节点的内容保留，内置插件随客户端更新；第三方插件仍可单独安装。在线图片与 AI 生成功能仍需联网。

本次支持直接登录 OneYes、双重验证和复用 OneYes Desktop v0.1.65 登录态。可一键配置或手动填写 Key，按 OpenAI SVIP/VIP、DeepSeek DeepSeek、Grok Video 分组复用或创建 Canvas_无限画布。连接诊断识别误删、停用、分组变更和模型变化，用户确认后修复缺失 Key，不重放付费任务。接口地址仍固定，不提供新增／删除其他渠道。独立登录信息本机加密，密码不保存，登录态复用不交付主客户端令牌。修复桌面自定义协议的 Axios 传输方式。

- 预置 OneYes 渠道，填写自己的 Key 即可接入，支持获取当前 Key 可用模型。
- OneYes 文生图、参考图编辑使用 SSE 流式传输，生图工作台可显示中间预览。
- 断流、524 不自动重放付费请求；桌面配置本机 AES-GCM 加密，不调用 macOS 钥匙串。
- Windows、macOS、Linux 均提供 x64 与 ARM64 包。SHA256SUMS.txt 包含全部安装包校验值。

Windows：选择 Windows-x64 / Windows-arm64 的 Setup.exe。
macOS：Apple Silicon 选择 macOS-arm64，Intel 选择 macOS-x64；提供 DMG / ZIP。当前为 ad-hoc 签名，未经 Apple 公证。
Linux：Intel/AMD 芯片选 x86_64 的 AppImage/RPM 或 amd64 的 DEB；ARM64 芯片选 arm64 的 AppImage/DEB 或 aarch64 的 RPM。

首次安装可能有系统来源确认。安装完成后 Canvas 可从系统应用入口独立启动，不要求 OneYes Desktop 常驻；真实 OneYes 付费生图由用户自行使用 Key 验证。流式能降低长等待导致的 524，仍依赖上游及时发送数据。
